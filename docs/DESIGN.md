## 设计概览

TabEx 使用 PyQt5 构建界面，通过 Windows Shell/COM 嵌入原生文件视图，而不是自行实现文件列表。

| 职责 | 主要模块 | 设计约束 |
|---|---|---|
| 启动与界面 | [app.py](../tabexplorer/app.py)、[mainwindow.py](../tabexplorer/mainwindow.py)、[explorer_tab.py](../tabexplorer/explorer_tab.py) | 单实例转发；主窗口组织标签、分屏与功能入口 |
| 导航与恢复 | [navigation.py](../tabexplorer/navigation.py)、[shellview.py](../tabexplorer/shellview.py) | 导航请求编号隔离过期回调；慢盘路径解析放入后台；Shell 视图操作仍在主线程 |
| 数据保存 | [json_store.py](../tabexplorer/json_store.py)、[persistence.py](../tabexplorer/persistence.py) | 校验结构、保留损坏文件、读取失败时阻止覆盖；原子写入配置与会话数据 |
| 搜索与文件任务 | [search.py](../tabexplorer/search.py)、[workers.py](../tabexplorer/workers.py)、[fileops.py](../tabexplorer/fileops.py) | 搜索流式返回；文件操作在后台执行，支持进度、取消与失败处理 |
| 日志与诊断 | [debuglog.py](../tabexplorer/debuglog.py)、[diagnostics.py](../tabexplorer/diagnostics.py) | 本地记录、调试日志轮转、诊断导出白名单与脱敏，不自动上传 |
| 构建与验证 | [build_release.py](../tools/build_release.py)、[validate_runtime.py](../tools/validate_runtime.py) | 隔离个人数据；回归与原生验证通过后才替换构建输出 |

数据目录与资源目录分离：源码运行默认使用项目目录，打包运行默认使用 EXE 所在目录。
`config/` 保存配置，`logs/` 保存日志；`TABEX_DATA_DIR` 可用于隔离运行数据。
内置工具放在 `tools/`，依赖清单放在 `requirements/`，打包资源不作为持久化数据目录。

### 数据保护与导航设计

以下机制由 v4.03 引入，后续版本保持不变：

- **数据保护**：配置、书签、聊天记录、常用目录和 AI 工作流统一使用 JSON 数据保护。文件不存在时正常初始化；读取失败、结构错误且无法保留备份时禁止自动覆盖，并报告原因。损坏文件使用带唯一后缀的备份名，同一秒内多次恢复也不会互相覆盖。API 密钥加密失败时拒绝保存，无法解密的原密文在其他配置修改时仍保留。
- **导航竞态**：新导航作废旧请求，包括线程已结束但完成通知仍排队的目录检查、旧失败回调和同地址重试前的超时；后台 Shell 控件也立即作废旧解析。旧视图的重复完成通知不会取消新检查，真正的原生目录切换则会丢弃过时检查。
- **慢盘路径**：地址栏先识别 UNC、OneDrive 和映射网络盘，再决定是否执行文件系统检查；中英文路径转换共享相同判断，不在这些路径上同步调用存在性检查。
- **日志轮转**：调试日志按实际 UTF-8 字节数限制，每份最多 5 MiB，保留 `.1` 至 `.3` 三份备份，总计最多约 20 MiB。超大单条记录安全截断，写入或轮转失败记录诊断并提示，恢复后可继续写入；轮转文件也按原白名单筛选后加入诊断导出。
- **职责拆分**：[navigation.py](../tabexplorer/navigation.py) 接管 26 个导航方法，保留文件标签的原有调用接口；[json_store.py](../tabexplorer/json_store.py) 统一校验、备份、覆盖保护和原子保存。没有重写界面或引入新的运行依赖。

**v4.03 验证基线**：新增 27 项优化回归，完整测试共 348 项，347 项通过、1 项离屏截图测试跳过；Python 编译和编辑器诊断检查通过。默认等待间隔下完成 2 轮预热、3 轮有效循环、130 个原生检查步骤，实际 Shell 目录、失败后恢复、排队导航顺序、连续分屏导航、日志隔离、单实例及正常退出检查通过，心跳 P95/P99 为 180/490 ms。测试只使用隔离数据，短测不等同于小时级长稳。

## 🆕 最近更新(只保留最新)

### v4.05 (2026-10-30)
- **原地自动刷新**：目录变化触发的自动刷新改为调用 `IShellView::Refresh`（同 Explorer 的 F5），不再重新导航到同一路径。选中项、滚动位置和用户切换的视图模式得以保留，也不再重建 DefView、重装双击钩子和重复强制详细视图；当前无视图或刷新失败时回退为重新导航。

<a id="runtime"></a>

## 🛠️ 运行环境

**从可执行文件运行**（推荐）：
1. 从 [Releases](https://github.com/caojinyuan/TabEx/releases/latest) 下载 `TabExplorer.exe`
2. 双击运行即可
3. 程序会在 `TabExplorer.exe` 同目录的 `config/` 中读写配置文件（源码运行时位于项目根目录的 `config/`）：
  - `config/config.json`：应用设置、固定标签、标题栏快捷方式、会话缓存、常用搜索；AI API 密钥以 Windows DPAPI 加密保存为 `api_key_protected`，只有当前 Windows 用户能解密
  - `config/bookmarks.json`：书签数据
  - `config/frequent_dirs.json`：常用目录的访问次数与最近访问时间
  - `config/ai_workflows.json`：AI 快捷工作流模板
  - 数据文件无法解析或根结构错误时，原文件在原目录保留为 `文件名.broken-日期-时间-唯一后缀`，可手动修复后改回原名；读取受阻或备份失败时不写回默认内容，须修复文件或权限后重启
4. 日志统一保存在程序同目录的 `logs/` 中：
  - `logs/TabEx_debug_latest.log`：最新调试日志
  - `logs/diagnostics/`：按会话保存的崩溃调用栈、事件、状态和资源趋势
5. `chat_history.json`（AI 聊天历史）的位置不变，仍保存在程序同目录。

升级时请先退出旧程序。读取配置时，若 `config/` 中缺少对应文件，会自动迁入根目录的旧文件，内容不变；若新旧位置同时存在，则使用 `config/` 中的版本，不覆盖或删除根目录旧文件。设置 `TABEX_DATA_DIR` 时，配置目录为该数据目录下的 `config/`，不会读取或迁移程序目录的个人配置。旧版 EXE 仍使用旧路径，需重新打包后才支持此布局。

**从源码运行**（Windows x64，无需预装 Python）：
1. 双击 `0_install_requirements.bat`：首次运行会下载固定版本 Python 3.13.13 x64，校验 SHA-512 后将完整运行时放到项目 `.venv/python-3.13.13/`，并安装依赖，不影响系统 Python，无需管理员权限
2. 双击 `1_run_TabEx.bat` 启动程序（仅使用项目本地 Python，不回退到系统 Python 或旧 `.venv/Scripts`）
3. 若使用 AI 功能，确保 `requests` 已安装并在 `config/config.json` 或设置界面中填写 AI 服务配置
4. VS Code 中选择 F5 配置 **TabEx (project Python 3.13.13)**。仓库的 [launch.json](../.vscode/launch.json) 明确指定项目解释器，并使用 `-E -s -X utf8` 隔离 Python 环境变量、用户包和文本编码；不会回退到旧解释器。首次缺少运行时或依赖时先执行安装脚本。正在运行的旧调试进程需要手动停止后重新启动。

通过“工具 → 关于 TabEx”可核对实际版本、源码/EXE 模式、启动时间、Python 版本、可执行文件路径、配置目录和实际日志目录；信息可选择复制，不会自动上传。

运行、安装和构建统一由 [tools/project_python.ps1](../tools/project_python.ps1) 管理解释器。它使用官方 Python NuGet 完整运行时（包含 pip，不是嵌入式精简包），依赖安装在本地运行时内，并隔离系统 Python 的环境变量、用户包和 pip 配置。首次需要访问 `api.nuget.org` 和 Python 包索引；下载的 Python 包缓存于 `.venv/cache/`，再次使用无需重复下载。`.venv/` 已被 Git 忽略，每个开发者从同一固定版本初始化。这里只用 `.venv` 收纳完整 Python，不创建额外虚拟环境，也无需激活。VS Code 调试请选择 `.venv/python-3.13.13/python.exe`。若检测到旧 `.venv/pyvenv.cfg`，脚本会先将旧环境整体备份到 `.venv-legacy-<唯一标识>/`，避免旧配置干扰新解释器；备份不会删除，且已被 Git 忽略。旧 `.python` 不会被删除，也不会被使用。

## 快捷键配置与实现

默认快捷键表见[项目首页](../README.md#shortcuts)。

在 `设置 → 手势与快捷键` 中可为每个命令改键：点击按键框后直接按下新组合，`×` 清空按键即停用，“恢复默认按键”一键还原。按键须包含 `Ctrl` 或 `Alt`（`F1`–`F24` 可单独使用）；保存时拒绝重复分配、占用 Explorer 文件操作键（如 `Ctrl+C/V/X/A/Z/Y`、`F2`、`Alt+Enter`）以及与 `Ctrl+1…9` 冲突的组合。`Ctrl+1…9` 只能整体启用或关闭。绑定保存在 `config/config.json` 的 `hotkey_bindings`，标题栏按钮提示和相关轻提示会显示当前按键。

快捷键由独立线程上的低级键盘钩子在按下时触发，不再每 60 ms 轮询按键状态；不拦截按键，只在本程序窗口位于前台时响应，按住不放不会重复触发。组合键按修饰键精确匹配：多按或少按 `Ctrl`、`Shift`、`Alt` 都不会触发，因此 Alt 组合键不再被 `Ctrl+Alt`（AltGr）触发，`F3`/`F4`/`F5` 带其他修饰键时留给 Explorer。`Ctrl+Shift+数字` 仍是 Explorer 的视图切换。钩子安装失败时自动退回原轮询方式。

<a id="usage"></a>

## 📖 主要功能说明

### 工作区与文件工具
标题栏搜索按钮旁的“工具”菜单提供（窄窗口收为图标，悬停仍显示名称）：
- **文件任务**：查看全部后台任务、取消、重试失败来源项、查看错误和清理完成记录。仍有文件任务时禁止退出，需等待完成或取消后再关闭。
- **任务续作**：失败后“重试失败项”，取消后“继续剩余项”。目录复制不会另建整份副本；成功文件仍存在且来源、目标身份未变化时跳过，发生外部修改时保留用户内容并报告冲突。取消不是回滚，已经完成的删除或重命名不会撤销。
- **命名工作区**：保存两侧标签顺序、重复路径、分组颜色、固定状态和各侧选中位置。打开工作区会追加标签，保留当前浏览内容；删除工作区记录不会删除文件。
- **目录差异比较**：默认采用分屏两侧目录，也可自行选择。后台递归比较内容，列出单侧存在、类型不同、内容不同和读取错误；双击结果打开对应目录并定位。目录链接不递归比较，每侧最多 100000 项。
- **比较后复制到另一侧**：在结果中多选差异项后点“复制到右侧 →”或“← 复制到左侧”，确认后作为后台文件任务执行。“仅一侧存在”的项直接复制，整个目录缺失时只复制该目录；“内容不同”的文件先把目标侧旧文件移入回收站再复制，移入失败的不复制；类型不同、读取失败的项跳过。目标已出现同名项时跳过，不生成副本。
- **分屏同步浏览**：按 `F3` 分屏后，在标题栏搜索按钮右侧的“工作区与文件工具”菜单 →“导航”中勾选。一侧进入子目录或返回上级时，另一侧按相同的相对路径移动，适合对照两个版本的工程目录；两侧起始目录相同也支持，跟随后可立即从任意一侧继续导航，无需等待。另一侧没有对应目录时只提示不移动。此功能只同步目录路径，**不联动滚动条、文件选中状态或文件内容**。跳到无关目录、切换标签不会带动另一侧；关闭分屏后自动关闭，不随会话保存。
- **常用目录**：见下文“常用目录跳转”。
- **批量重命名预览**：对当前面板选中项的文件名执行文本替换，预览完整映射后确认。拒绝非法名称和冲突，不覆盖目标；执行失败时在任务面板显示，已完成项不会自动回滚。
- **永久删除**：独立确认窗口列出目标，不进入回收站。包含目录链接的递归永久删除会被拒绝。

AI 的 `PATCH_FILE` 和 `WRITE_FILE` 在写入前展示差异；预览后发现文件变化则拒绝写入。补丁目标必须唯一，保留原编码和换行，补丁预览文件上限 5 MB。原有大于 5 KB 文件禁止整体覆盖的限制保留。

**取消边界**：复制按 1 MB 分块检查取消；正在执行的磁盘或网络系统调用返回前无法中断。已成功复制、重命名或移入回收站的项目不会因取消自动撤销。复制目录中的已完成文件会保留。

### 分屏操作与功能发现
- 开启分屏后，书签栏下方显示紧凑操作条：**同步导航：关/开**、**目录差异比较**及**当前操作侧**。菜单和操作条共用同一个同步开关，状态持续可见；关闭分屏后隐藏操作条并关闭同步。
- 同步导航只同步进入子目录和返回上级，**不联动滚动条、选中项或文件内容**。未分屏时菜单中的同步项不可用，并提示“请先开启左右分屏”。
- 搜索、前进/后退、终端和 Git 按钮提示会标明作用于哪一侧及当前路径。搜索在“此电脑”等虚拟位置不可用，提示先打开文件夹。
- 按 `Ctrl+Shift+P` 或进入“工具 → 查找功能”，搜索“同步”“比较”“工作区”“截图”或快捷键。上下键选择、回车执行、`Esc` 取消；不可用操作仍可查到并说明原因。命令搜索复用原有操作，删除、重试等确认不会绕过。
- “常用目录”“查找功能”等菜单按键及工具提示跟随自定义快捷键更新；停用的快捷键不再显示。
- 文件任务失败通知提供“查看失败项 / 重试”入口，点击后选中对应任务；在任务面板查看错误或确认重试。错过通知仍可点击标题栏任务计数查看，取消任务仍可继续剩余项。

### 标签分组增强（F4）
- 按 `F4` 时：若当前标签未分组，则对“当前标签及其左侧连续未分组标签”创建同色分组
- 再按 `F4` 时：仅取消当前标签分组并转为未分组，不影响左侧已有分组标签
- 右键整组拖动时：被拖动组保持原分组颜色，不受目标位置原有分组颜色同化
- 若整组插入到目标分组中间：目标分组会被拆分，右半段自动分配新颜色，形成两个独立分组
- 分组标签右键：**命名分组**（组名显示在组首标签左侧）、**折叠/展开分组**、**取消分组**（整组取消并移到未分组区域）、**关闭该分组**
- 折叠后只保留组首标签，左侧显示 `▸ 组名 · 数量`；点击该名称标签即可折叠/展开。通过查找标签、会话恢复等方式选中被折叠的标签时自动展开；`Ctrl+Tab` 和 `Ctrl+1…9` 只在可见标签间切换；拖到折叠组组首之后的标签会放到整组后面
- 分组状态会进入会话快照：重启后可恢复分组颜色、组名和折叠状态；同路径重复标签页也按数量和顺序恢复

### 标签右键菜单
- **复制路径**：复制该标签当前路径，分隔符按 `设置 → 路径栏分隔符设置`
- **复制标签**：在原标签右侧打开同一路径的新标签，并加入原标签所在分组
- **移到右侧 / 移到左侧**：在左右两组之间移动标签；未分屏时“移到右侧”会开启分屏；左侧至少保留一个标签
- **关闭其他标签 / 关闭右侧标签**：只作用于同一侧，固定标签保留；关闭的标签可用 `Ctrl+Shift+T` 逐个恢复

### 常用目录跳转
- 标签在某个本地或网络共享目录停留超过 1.5 秒即计为一次访问；`此电脑`、`回收站` 等虚拟位置不记录
- 按 `Ctrl+J`（或工具菜单 → `常用目录...`）打开列表，按访问次数和最近访问综合排序（最近 1 小时、当天、一周内的访问权重更高）
- 输入多个关键词筛选（都需出现在路径中，不区分大小写），`↑`/`↓` 选择，`Enter` 在当前标签打开，`Ctrl+Enter` 在新标签打开，`Delete` 移除记录
- 记录保存在 `frequent_dirs.json`，最多 500 条，访问总数过多时整体衰减，让近期常用目录靠前；快捷键可在设置中改键或停用

### Everything 搜索（推荐）
1. 只需安装并启动 [Everything](https://www.voidtools.com/) 并等待索引完成；命令行工具 `es.exe` 已内置在工程的 `tools/` 目录并会被打包进 `TabExplorer.exe`，无需单独下载或在设置中指定路径
2. 在 TabExplorer 中按 `Ctrl+F` 打开搜索，勾选"使用 Everything"即可享受毫秒级搜索；Everything 不支持搜索文件内容（只搜索文件名），启用后“搜索文件内容”不可用，需搜内容请取消勾选，结果中的文件夹显示为 📁 和“文件夹”类型

### 流式内容搜索与匹配预览
- 取消勾选 Everything 并勾选“搜索文件内容”。只搜内容时，直接消费 ripgrep 结果，不重复遍历目录；同时勾选文件名时合并两种结果，同一文件只显示一次。
- 结果流式到达，不必等待整棵目录扫描结束。每个文件保留首个内容匹配的位置；列表下方显示行号和最多 500 字符的片段，点击“在 VS Code 中打开匹配行”跳转。文件名命中及备用 Python 引擎结果不提供行预览；双击结果的原有“打开所在目录”行为不变。
- UTF-8/UTF-16 和 GBK 搜索仍受支持；遇到不兼容正则或引擎错误会明确提示并回退，保留已经显示的结果且不重复添加。只缓存完整且没有警告的小结果集。
- 搜索队列和管道读取均有界；单条 JSON 匹配记录超过 1 MiB 时保留文件命中，但不提供行号跳转或完整行预览。达到结果上限和主动停止都会结束 ripgrep，关闭窗口后不会继续向界面写结果。

### 上下文外部工具
- 入口：“工具 → 外部工具 → 配置外部工具”，或“设置 → 工具集成 → 配置外部工具”。工具也可从 `Ctrl+Shift+P` 查找功能和搜索结果右键菜单调用。
- 内置预设：VS Code 打开当前目录 / 选中项 / 匹配行 / 比较两个文件；WinMerge 比较两个选中项 / 左右目录。只调用本机工具，不自动下载；会检测 PATH 和常见安装位置，也可以手工选择 EXE。没有安装时会明确提示。已有配置不会被覆盖，新增预设可通过“添加缺少的预设”加入。
- 配置窗口自动在后台检测每个程序，显示“已就绪”“未安装或未找到”“路径失效”以及解析后的实际路径；修改路径后可重新检测。未找到的工具在完成检测后会显示不可用原因，安装或修复路径后请再次检测。
- “打开官方下载页”只打开 WinMerge / VS Code 官方网页，不下载或安装软件。“预览启动参数”显示独立参数列表和工作目录，不执行程序；缺少单选、双选、分屏或匹配行上下文时明确解释原因。
- **尚未安装 WinMerge**：从 [WinMerge 官方下载页](https://winmerge.org/downloads/) 获取 x64 安装包；没有管理员权限可选 Per-user Installer，或下载 ZIP 便携版并解压。打开配置窗口，分别选中两个 WinMerge 预设，通过“程序”右侧的文件夹按钮选择安装或解压目录中的 `WinMergeU.exe`，其余参数保持默认，确认保存。不安装 WinMerge 也可以继续使用 TabEx 自带的“目录差异比较”。
- **找不到配置入口**：按 `Ctrl+Shift+P` 搜索“配置外部工具”，或进入“设置 → 工具集成”。旧进程不会自动加载新代码；退出旧进程后使用 [1_run_TabEx.bat](../1_run_TabEx.bat) 启动新版源码。旧 `TabExplorer.exe` 必须经 [2_build_exe.bat](../2_build_exe.bat) 重新构建才包含新入口。
- 每行填写一个参数，**路径无需加引号**；多个选中项各自成为一个参数，空格、中文和 `&` 不会被当作命令分隔符。程序必须是 EXE；脚本通过对应解释器及独立参数调用。工作目录默认 `{cwd}`。

| 占位符 | 含义 |
|---|---|
| `{cwd}` | 当前操作侧的目录；搜索结果菜单中为文件所在目录 |
| `{selected}` | 所有选中项；必须单独占一行 |
| `{file}` | 恰好一个选中项 |
| `{file1}` / `{file2}` | 恰好两个选中项，按选择接口返回的顺序 |
| `{left}` / `{right}` | 分屏左右两侧目录 |
| `{line}` / `{column}` | 内容搜索结果的位置，仅匹配行上下文有效 |

- 缺少所需上下文时，菜单禁用该项并在提示中解释。参数模板中的字面大括号使用 `{{` / `}}`。配置保存在 `config.json` 的 `external_tools`，取消配置窗口不会保存修改；“添加缺少的预设”不会覆盖自定义路径。
- 自定义工具会执行你配置的程序和参数；是否修改文件或访问网络由该工具决定。TabEx 不随包分发 WinMerge / VS Code，也不替它们上传文件。原有标题栏启动区保持不变。

### 工程搜索与排除规则
- 默认“全量搜索”且无排除规则，保留原来的文件/文件夹搜索行为。切到“工程文件”后遵守 Git/ripgrep 忽略规则（即使目录没有 `.git` 也读取 `.gitignore`），跳过隐藏项，并排除 `.git`、`node_modules`、`.venv`、`__pycache__`、`build`、`dist` 目录。
- 排除规则相对于搜索目录，使用分号分隔，例如 `build/;*.log;vendor/**`；`build/` 表示任意层级的同名目录。使用 ripgrep glob 语义，规则不需要 `!` 前缀，Windows 下排除匹配不区分大小写。
- **工程模式或启用排除规则时，只返回文件，不列出目录结果，且禁用 Everything。** 文件名枚举、内容搜索和不兼容正则的 Python 备用扫描共用 ripgrep 的范围规则；组件缺失或范围解析失败会报错，不偷偷扩大为全盘搜索。恢复全量行为需选择“全量搜索”并清空排除规则。
- 范围和排除规则随“常用搜索”保存，不保存路径。修改类型过滤不会重新纳入已被忽略的工程文件。

### 目录比较到内容差异
- 比较结果可筛选全部、仅左侧、仅右侧、内容不同、错误或未比较项；切换筛选会清除原选择，隐藏项不会被复制。
- 选择一条“内容不同”的文件结果，选择 VS Code 或 WinMerge 后点击“查看内容差异”，自动传入左右两个文件。优先使用配置过的比较预设；没有配置时在工具名称中明确标为“默认预设”，不会改写工具配置。
- 双击仍保持原来的打开目录定位行为。查看差异不自动复制；确认内容后再使用“复制到左侧/右侧”，仍经过原有确认和文件任务流程。

### 跨目录文件收集篮
- 在文件面板选中项目，使用“工具 → 添加选中项到收集篮”；搜索结果支持 Ctrl/Shift 多选，并提供同名按钮及右键入口。重复路径只保存一次。
- 从“工具 → 文件收集篮”查看引用。可复制路径，或把项目复制到主窗口当前操作侧的目录；有选择时只操作所选项，没有选择时操作全部，复制前会列出目标并确认。
- 复制复用文件任务队列、取消和失败记录；同名项保留两者，不覆盖已有文件。来源被移动/删除时会在文件任务中明确报告，不会从收集篮静默移除。
- 移出或清空只删除引用，不删除原文件；关闭收集篮窗口保留列表，退出 TabEx 后清空，不写入个人配置。

### 推荐的日常组合用法
1. 用“命名工作区”保存工程源码、输出和文档等常用标签组合。
2. 保存“工程源码”“最近修改”“日志”等常用搜索；日志搜索使用全量模式，并按需要清空排除规则。
3. 用 `Ctrl+J` 跳常用目录，用 `Ctrl+Shift+P` 查找功能或外部工具。
4. 对照两个版本时使用“分屏 → 同步导航 → 目录比较 → 查看内容差异 → 确认复制”。
5. 跨多个目录整理交付文件时先加入收集篮，最后统一复制，避免反复覆盖剪贴板。

### 搜索筛选与常用搜索
- **正则**：勾选后关键词按正则表达式匹配文件名和文件内容（Python 语法，可与“区分大小写”“全词匹配”组合）。内容搜索优先交给 ripgrep，ripgrep 不支持的写法（如反向引用）自动改用 Python 扫描；Everything 使用其 `-r` 正则搜索。超过 2 MB 的文件分块扫描时，跨越分块边界的匹配可能漏掉
- **大小**：填写最小/最大值，支持 `B`、`KB`、`MB`、`GB` 和小数（如 `1.5GB`）；设置大小后只显示文件
- **修改时间**：不限 / 今天 / 最近 7 天 / 最近 30 天 / 最近一年，对文件和文件夹都生效
- 大小和日期筛选在结果入列前精确检查；Python 备用引擎在读内容前筛选，ripgrep 流式模式可能已读取不符合筛选的文件。关键词留空时可直接列出符合条件的文件（如“大于 100MB”）。Everything 模式会把大小和日期传给 Everything 预筛，再由程序精确过滤
- **常用搜索**：右侧“常用搜索”按钮可保存当前条件（关键词、文件类型、各选项和筛选），之后一键套用或删除；不保存搜索路径，套用后作用于当前路径。保存在 `config.json` 的 `search_presets`

### QuickLook 空格预览（可选，默认关闭）
类似 macOS 的“快速查看”：在文件列表选中文件，按一下空格就弹出预览窗口（图片、文本/代码、Markdown、PDF、Office、压缩包、音视频等），再按一次空格关闭。

**第一次使用（只需做一次）**
1. 点击标题栏的设置按钮，打开 **设置 → 工具集成**，找到“QuickLook 预览”分组
2. 点击 **“下载 QuickLook 4.5.0（约 60 MB）”**。状态行会显示下载进度；网络慢时可点“取消下载”，再次点击会从断点继续，不用从头来
3. 下载完成后会自动校验并解压，按钮变成“已下载”，状态行显示可用路径
4. 勾选 **“启用 QuickLook 预览（在文件列表选中文件后按空格）”**，点击“确定”保存

**日常使用**
1. 在任意标签页的文件列表中点选一个文件（或文件夹；多选时预览选中的第一项）
2. 按 **空格** 弹出预览；首次弹出会先启动 QuickLook，需要 1～2 秒
3. 再按一次 **空格** 关闭预览

**注意事项**
- 只在焦点位于文件列表时生效：重命名、地址栏/搜索框输入、目录树里按空格都不会触发；刚输入过字母或数字的 0.8 秒内也不触发，所以按名称定位带空格的文件名不会被打断
- 勾选了但还没下载时，按空格会提示“尚未下载 QuickLook”，不会弹窗打扰
- 不想用了：取消勾选并保存即可；想彻底清除可删除程序目录下的 `QuickLook/` 文件夹
- 预览窗口会在任务栏显示按钮，被盖住时点任务栏按钮即可调回；窗口要等 QuickLook 加载完内容才会出现，大文件可能需要几秒
- 本程序启动的 QuickLook 空闲 20 分钟后会自动结束以释放内存，再按空格会重新启动
- QuickLook 是 GPL v3 开源软件，不随本程序分发，只在你点击下载时从官方 GitHub 发布页获取固定版本并校验 SHA256；本程序启动的 QuickLook 会在退出 TabExplorer 时一并结束，已自行安装的 QuickLook 则会被直接使用，不受影响
- 排查：空格没反应时，依次确认已勾选启用、状态行显示“可用”、焦点在文件列表（先点一下文件）；仍无效可在设置中开启调试模式，日志里会记录 `[QuickLook]` 相关信息

### 自动监听 Explorer 窗口
- 类似 Clover 的核心功能
- 新打开的 Windows 资源管理器窗口自动嵌入为标签页
- 通过系统窗口显示事件即时发现新窗口，并至少每 10 秒兜底扫描一次；事件不可用时按设置中的间隔轮询
- 发现后先隐藏原窗口再读取路径，减少闪现；控制面板或无法读取路径时恢复显示原窗口
- 可在设置中启用/禁用
- 若嵌入式 `Shell.Explorer` 控件初始化失败，会自动回退为使用系统资源管理器打开，避免生成异常标签页或拖慢界面

### 智能自动刷新
- 当前标签页会同时使用目录 watcher、文件 watcher 和低频轮询兜底检测文件变更
- 编辑当前目录里的文件后，列表、修改日期、大小等信息会更可靠地自动刷新
- 后台标签页不会持续高频轮询，只在切回时按需补刷新
- 这种策略兼顾了及时刷新和多标签场景下的性能开销
- 标签右键 `⏸ 冻结自动刷新` 可暂停该标签的自动刷新，适合持续写入的日志或编译输出目录；冻结期间的变化只做记录，`▶ 恢复自动刷新` 时如有变化补刷新一次。切换目录后仍保持冻结，`F5` 手动刷新不受影响；冻结状态不随会话保存，重启后恢复自动刷新
- 当当前目录正好是程序运行目录时，会自动忽略应用自身写出的配置/日志文件变化，避免 watcher 与会话快照互相触发导致刷新风暴
- 配置写盘与上次写入的内容比较，内容未变时不读盘也不写盘

### 后台标签休眠
- 后台标签超过设定时间未访问时释放其文件视图，减少多标签长期运行的内存和句柄占用；切回时按当前路径重新加载
- 默认 30 分钟，在 `设置 → Explorer监听设置 → 后台标签休眠` 修改，`0` 表示关闭
- 两侧当前显示的标签、正在导航的标签和有后台文件任务的标签不会休眠；标签历史、分组和固定状态不受影响
- 重新加载后不保留滚动位置和选中项；休眠标签的悬停提示会注明状态

### 深色主题
- 在设置窗口底部“主题”中选择：**跟随系统**（默认）、浅色、深色、灰色（比深色更亮的深色变体），保存在 `config.json` 的 `theme`（`system` / `light` / `dark` / `gray`）
- 跟随系统时读取 Windows `设置 → 个性化 → 颜色 → 选择应用模式`，系统切换后约半秒内自动跟随，无需重启
- 标题栏、工具栏图标、标签栏、路径栏、状态栏、搜索/设置等对话框、AI 助手及内嵌资源管理器视图（文件列表、目录树、命令栏）一起换色；文件区右键菜单等原生菜单同时按深浅色显示
- Windows 的资源管理器视图只在新建时完整应用配色，因此切换主题时会按当前路径重建各标签的视图（后台标签在切回时重建），滚动位置和选中项不保留；若正在进行系统复制/移动，重建会等操作窗口关闭后再进行
- 原生视图与菜单的深色依赖 Windows 10 1903 及以上的系统接口；更早的系统只切换程序自身界面

### 界面语言与开机启动
- **界面语言**：在设置窗口底部“语言 / Language”中选择中文或 English，保存在 `config.json` 的 `language`（`zh` / `en`）。保存后新打开的菜单、对话框和提示立即使用新语言，部分已显示的界面需重启后切换。所有经 `tr()` 显示的界面文字都有英文，回归测试会拦下缺少英文或占位符不一致的文字
- **开机启动**：在 `设置 → 常规 → 开机启动设置` 勾选后，在当前用户的启动文件夹（`%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup`）创建指向 `TabExplorer.exe` 的 `TabExplorer.lnk`，取消勾选即删除。源码运行时需在程序目录或其上级目录存在 `TabExplorer.exe`，否则提示失败。EXE 移动位置后，若快捷方式指向的旧程序已不存在，启动约 5 秒后自动改为当前位置；旧程序仍存在时不自动改动，设置窗口会提示当前指向，保持勾选并点“确定”即改为当前程序

### 网络位置断线提示
- 打开 UNC 路径或映射网络盘失败、超过 20 秒无响应，或在已断开的共享中打开子文件夹失败时，标签顶部显示提示条：路径、系统给出的原因（如“找不到网络路径”“用户名或密码不正确”）和处理建议；提示条保留到导航成功或手动关闭，不再是一闪而过的通知
- **重试**：重新打开该位置，适合网络或 VPN 恢复后使用
- 首次导航失败出现空白占位时，可在地址栏改为有效父目录继续浏览；错误提示仍显示时，输入同一路径也可重试。以原生文件视图实际导航完成为准，不会仅改变地址栏而一直等待隐藏的视图。
- **重新连接**：UNC 路径重新建立到共享的连接，映射盘恢复已记住的连接；需要凭据时由 Windows 弹出登录框，连接成功后自动重新打开。连接在后台线程进行，等待期间可以切换其他标签；若期间已导航到别处，完成后不会把你带回去
- 启动时恢复的网络标签若连不上，标签保留并显示提示条；打开网络书签和恢复固定标签时不再在界面线程探测网络路径是否存在，断网时不会因此卡住界面，固定的网络标签也不会被当作不存在而丢弃
- 本地路径不存在等其他错误仍按原方式提示。正在执行的网络系统调用无法中途取消，重试会开始新的连接尝试

### 当前目录快捷定位

### AI 助手
- 在 `设置 → AI 助手设置` 中配置启用开关、API 地址、API Key、模型名、面板宽度和系统提示词；“获取模型”在后台读取模型列表，网络慢时设置窗口不会卡住；“快速选择”预设会同时填入地址和模型名
- **证书校验**：AI 请求和获取模型默认校验 HTTPS 证书与主机名，同时信任 Windows 证书库（含企业根证书和公司 SSL 检查代理的证书）与 certifi 公共根证书。内网自签名服务无法通过校验时，可勾选“允许不受信任的 HTTPS 证书”（`ai_chat.allow_insecure_tls`，默认关闭）；勾选后 API Key 和发送的文件内容可能被中间人截获
- **密钥保存**：API Key 用 Windows DPAPI 加密后写入 `config.json`（`api_key_protected`），只有当前 Windows 用户能解密；旧版本的明文 `api_key` 在下次保存配置时自动转为密文。把配置复制到其他电脑或用户后无法解密，启动时会提示重新填写
- 聊天记录原子写入；保存失败会提示。`chat_history.json` 无法解析或根结构不是列表时，原文件改名保留为 `.broken-日期-时间-唯一后缀`；读取失败或无法备份时禁止后续消息覆盖原文件，修复后重启再加载
- 标题栏 `🤖` 按钮仅在 AI 开关启用时显示
- 支持 OpenAI 兼容接口，也支持本地/内网模型服务
- AI 默认只在用户明确要求时输出操作指令，避免普通问答误操作
- 在搜索结果列表中，右键文件可使用 `🤖 AI分析此文件`，快速输出用途/关键逻辑/风险点/下一步阅读建议
- 在搜索窗口中可点击 `🤖 AI总结结果`，对当前结果做目录分布、核心文件和阅读顺序总结
- 支持将目录直接拖入 AI 面板：自动生成目录结构预览；若输入框为空会自动发起目录结构分析
- 拖拽文件到 AI 面板时，若输入框为空会自动发起文件分析；若输入框已有内容则仅展示内容，避免打断手动提问
- AI 面板提供快捷工作流按钮：`目录巡检`、`代码审阅`、`变更说明`，点击后会自动注入预设提示词并启动多步分析
- 快捷工作流模板存放在独立文件 `config/ai_workflows.json`（不占用 `config/config.json`），可按需自定义模板内容

### 检查更新
- 手动检查：工具菜单 `检查更新...`，或设置窗口底部的“立即检查”；会明确提示“已是最新版本”、新版本或失败原因，点击“查看更新”在浏览器打开发布页。只提示，不下载、不安装
- 自动检查默认关闭。在设置窗口底部勾选“自动检查新版本”后，启动 30 秒后及长期运行期间每天最多查询一次；同一新版本只提醒一次，失败（如离线、被代理拦截）时不提示，稍后自动重试
- 发布标签（如 `v1.13.0`）与软件版本号（如 `3.75`）不同，程序会读取该标签下 `TabEx.py` 开头的 `APP_VERSION` 再比较。访问 `api.github.com` 与 `raw.githubusercontent.com`，不上传任何本地数据；未登录的 GitHub 接口每小时有次数限制，公司网络共用出口时可能暂时被限流

**当前支持的 AI 指令：**
- `OPEN_DIR`：打开或切换目录
- `READ_FILE`：读取文件内容，自动分段读取大文件
- `LIST_DIR`：列出目录内容
- `MKDIR`：创建目录
- `PATCH_FILE`：局部修改已有文件（精确替换片段，优先用于改代码）
- `WRITE_FILE`：写入/覆盖文件
- `DELETE`：删除文件或目录（需确认）
- `RUN_SCRIPT`：运行脚本（需确认）
- `GIT_STATUS`：查看仓库状态（分支、暂存/未暂存变更）
- `GIT_DIFF`：查看未提交变更的 diff
- `GIT_LOG`：查看最近提交历史（默认最近 20 条）
- `GIT_BRANCH`：查看本地/远程分支列表
- `GIT_ADD`：暂存变更（需确认）
- `GIT_COMMIT`：提交暂存区变更（需确认）
- `GIT_SWITCH`：切换分支（需确认）
- `GIT_RESTORE`：还原工作区改动（需确认）
- `GIT_RESET_SOFT`：软重置到指定提交（默认 `HEAD~1`，需确认）
- `GIT_PULL`：拉取远程更新（可选远程/分支，需确认）
- `GIT_PUSH`：推送本地提交（可选远程/分支，需确认）

**安全限制：**
- AI 文件操作仅允许在发起请求时的标签目录范围内执行；切换标签不会改变授权目录，虚拟目录不会回退到程序目录。`OPEN_DIR` 是导航命令，可打开其他目录，但不会扩大当前请求的文件操作授权范围。
- Git 暂存/还原只接受范围内的明确路径，不支持通配符或特殊 pathspec；提交、切分支、重置、拉取和推送要求仓库根目录也处于授权目录内。脚本即使位于授权目录内，启动后仍具有当前用户权限，不是沙箱。
- 覆盖文件、删除文件/目录、运行脚本都需要用户手动确认
- Git 写操作（`GIT_ADD` / `GIT_COMMIT` / `GIT_SWITCH`）需要用户手动确认
- Git 风险操作（`GIT_RESTORE` / `GIT_RESET_SOFT` / `GIT_PULL` / `GIT_PUSH`）需要用户手动确认
- 聊天面板支持拖拽本地文件进行快速阅读，单文件读取大小有限制
- 操作在后台按回复顺序执行，可取消后续操作；已完成的修改不会撤销，阻塞中的磁盘/网络系统调用返回前无法立即终止。退出时若仍有 AI 文件操作，会先请求取消并等待结束。

### 崩溃诊断包
重启后打开标题栏 **工作区与文件工具 → 导出崩溃诊断包...**，确认收集范围并选择 ZIP 保存位置。默认文件名为 `TabEx-diagnostics-YYYYMMDD-HHMMSS.zip`，打包在后台进行，完成后显示文件位置；导出过程中暂不允许退出程序。不会自动上传。反馈时提供检查过的 ZIP 和大致崩溃时间、当时操作即可，无需逐个挑选日志。

- 基础诊断不依赖 Debug 开关：自动记录运行版本、Python/Qt 版本、系统类型、主线程及 Python 后台线程的未处理异常、Qt 严重/致命错误。旧式详细调试日志只有启用调试输出后才更丰富。
- 详细调试日志每份上限 5 MiB，保留 `TabEx_debug_latest.log.1`、`.2`、`.3`，加当前文件总计不超过约 20 MiB；按 UTF-8 字节数而非字符数判断，单条超限时保留合法 UTF-8 并附截断说明。写入/轮转失败会进入诊断记录，并在主窗口诊断检查时提示一次；恢复后继续写入。
- 每 10 秒保存一次状态快照，包括内存、线程数、保留中的 Qt 线程类别、标签数量、搜索窗口数量和最近 50 个文件任务的计数与进度。未处理 Python 异常仅保留类型及调用位置，不记录异常消息、局部变量或源码行。
- 资源趋势：启动后及每 10 分钟向 `resources.jsonl` 追加一条资源计数（内存、线程数及按名称分组的线程、标签与休眠标签、运行中的后台线程和文件任务、搜索窗口及通知数量），不含路径。与异常事件分开轮转，长时间运行不会挤掉崩溃记录。该记录取代旧版需要在设置中开启的资源快照日志。
- 启动前保留上一份调试日志中指定诊断类别的片段；每次启动使用独立会话目录，避免覆盖上次错误。正常退出记录 `closed`，捕获异常记录 `error`，Qt 致命错误记录 `fatal`；仅有 `running` 且无结束时间不等于确认崩溃，也可能是强制退出或另一个仍运行的实例。
- 日志默认保存在程序目录的 `logs/`，诊断会话位于其中的 `diagnostics/`；不可写时依次回退到 `%LOCALAPPDATA%\TabEx\logs`、`%TEMP%\TabEx\logs`，调试日志与诊断记录始终使用同一选定目录。“关于 TabEx”可查看实际位置。所有位置均不可写则报告错误并继续启动，诊断导出不可用。
- 旧版 `%LOCALAPPDATA%\TabEx\diagnostics`、`%TEMP%\TabEx\diagnostics` 和备用日志目录中的非活跃会话会迁入当前诊断目录；跨盘迁移先完整复制再删除原会话，不覆盖同名目标或移动仍活跃的会话。迁移失败保留原文件并记录错误。启动时清理超出最近 5 次的非活跃会话，不删除仍在运行实例的记录。
- 设置 `TABEX_DATA_DIR` 时，调试和诊断日志仅写入该目录下的 `logs/`；不迁移用户目录的旧会话，也不回退到共享日志目录。根目录的旧调试日志仅在新目录缺少对应文件时迁入；启动前仍会保留指定诊断类别的片段，然后重置本次调试日志。
- ZIP 包含清单、最近最多 5 个会话的状态/事件/调用栈以及筛选后的当前调试日志和最多 3 份轮转备份，每个文件最多取尾部 256 KiB；轮转备份使用与当前日志相同的标签白名单和脱敏规则。事件日志和资源趋势各自达到 256 KiB 后轮转，各保留一个备份。包内 `session.json` 记录版本及运行模式，`snapshot.json` 记录任务状态，`events.jsonl` 记录事件，`resources.jsonl` 记录资源趋势，`fault.log` 保存可用的线程栈；部分文件可能因没有对应记录而缺失。
- 不收集配置、书签、聊天历史、浏览文件内容、完整环境变量或内存转储。导出时替换路径、URL、邮箱及常见凭据字段；自动脱敏不是绝对保密保证，分享前请检查 ZIP 内容。原生调用栈在本地可能含路径，不应直接分享原始诊断目录。
- 原生故障使用 `faulthandler` 尽力捕获；若外部调试器已启用该处理器，则不覆盖它，并在会话中标明 `external-handler`，仍支持 Qt 致命错误的显式线程栈记录。强制结束、断电及部分原生崩溃可能没有调用栈，不能保证仅靠诊断包就定位所有问题。

.\.venv\python-3.13.13\python.exe -s -X utf8 tools\validate_runtime.py --seconds 10 --tabs 10
.\.venv\python-3.13.13\python.exe -s -X utf8 tools\validate_runtime.py --scenario lifecycle --cycles 50 --seconds 5 --report artifacts\lifecycle.json

验证器使用临时 `TABEX_DATA_DIR` 和 `LOCALAPPDATA`，配置与日志分别写入临时数据目录的 `config/` 和 `logs/`，不加载个人配置、书签、聊天记录或历史诊断，也不开启外部 Explorer 监听。数据目录与资源目录独立，不修改用户配置。测试会短暂显示真实原生窗口，不要手工操作该窗口。报告包括首个视图就绪耗时、Qt 心跳 P95/P99/最大延迟、内存、句柄、线程和标签计数，以及单实例、导航和正常退出结果。截图是人工检查材料，不等于自动视觉正确性判定。

默认 `smoke` 场景保留原来的启动/标签/导航/单实例/退出检查。`--scenario lifecycle` 增加原生分屏双向连续导航、关闭分屏、标签休眠/唤醒/关闭、搜索取消/关闭/重开、排队复制取消后续作、来源文件缺失后的重试、临时输出清理、最小化恢复。复制结果按字节验证；删除仅针对验证目录中的已知临时输出。重试确认由验证器在隔离窗口中自动点击，不改变正式运行时的确认行为。

生命周期场景默认先预热 2 轮，再在相同的单标签、无后台任务、搜索窗口已关闭的状态下建立资源基线。`--cycles` 是预热后的最低循环数，`--seconds` 是预热后的最低运行时长，两个条件都满足才完成；`--settle` 控制每轮检查前的安静等待时间，默认 1 秒。不额外强制垃圾回收。每一步有 30 秒超时，总时限可用 `--timeout` 设置。运行器返回非零退出码表示失败，报告保存失败阶段和具体原因。

默认验收预算（可用 `--limits limits.json` 覆盖同名字段）：

| 指标字段 | 相对预热基线的增长上限 / 心跳延迟上限 |
|---|---:|
| `commit_mb` | 私有提交内存增长 128 MB |
| `handles` | 句柄增长 128 |
| `gdi_objects` / `user_objects` | 各增长 32 |
| `python_threads` | Python 线程增长 2 |
| `dialogs` | 额外 Qt 对话框增长 0 |
| `heartbeat_p95_ms` / `heartbeat_p99_ms` | 200 ms / 1000 ms |
| `heartbeat_max_ms` | 5000 ms |

资源预算逐轮检查，任一超限立即失败；心跳在结束时判定。P95/P99 使用全程计数、10 ms 桶宽的有界直方图，最大延迟保留全程最大值，不因长时间运行丢掉早期卡顿。资源快照最多保留约 600 条，基线单独保留；报告还包含有效循环数、实测时长和最终资源增量。预算用于同机同场景回归，不是所有电脑的普遍性能承诺；调整预算应有基线依据，不能把提高预算当作修复。

原生导航仍由主线程中的 Windows Shell/COM 实现，Shell 扩展或网络盘导致的停顿不保证完全消除。自动循环使用本地临时目录，不包含真实断网、睡眠恢复或跨屏切换；长稳命令可运行数小时，但短测通过不等于小时级验证通过。

- `tools/rg.exe` - ripgrep 15.2.0（MIT/Unlicense），“搜索文件内容”优先使用它扫描，失败时自动回退到 Python 扫描；打包时嵌入 EXE，许可证文本在 `third_party_licenses/`
- `tools/7zr.exe` - 7-Zip 独立命令行解压器（LGPL），仅用于解压下载的 QuickLook 便携包；打包时嵌入 EXE
- `config/` - 本地配置目录，包含应用设置、书签、常用目录和 AI 工作流模板；不随仓库或 EXE 分发
- `logs/` - 本地调试日志与崩溃诊断会话；不随仓库或 EXE 分发
- `tabexplorer/quicklook.py` - QuickLook 下载（断点续传、哈希校验）、解压与空格预览调用
- `tabexplorer/frequent.py` - 常用目录记录（frecency 排序、`frequent_dirs.json`）与跳转窗口
- `tabexplorer/` - 功能模块（按依赖从底层到上层）：
  - `paths.py`（数据目录与路径工具）、`i18n.py`（界面翻译）、`constants.py`（全局常量）
  - `json_store.py`（JSON 校验、备份与原子保存）、`navigation.py`（导航请求、回调顺序与失败恢复）
  - `debuglog.py`（调试日志与诊断接入）、`diagnostics.py`（崩溃诊断记录）、`system.py`（进程资源与外部程序启动）
  - `hotkeys.py`（快捷键与键盘钩子）、`screenshot.py`（屏幕截图）、`title_shortcuts.py`（标题栏快捷方式）、`widgets.py`（提示、图标等通用控件）
  - `commands.py`（复用现有操作的功能搜索）、`runtime_validation.py`（原生验收与资源/延迟门槛）、`runtime_scenarios.py`（隔离生命周期循环）
  - `updates.py`（检查更新）、`workers.py`（后台线程）、`search.py`（搜索）、`fileops.py`（文件任务与目录比较）
  - `pathbar.py`（面包屑地址栏）、`bookmarks.py`（书签）、`shellview.py`（嵌入资源管理器视图）、`explorer_tab.py`（文件浏览标签页）
  - `tabbar.py`（标签栏）、`chat.py`（AI 助手）、`settings.py`（设置窗口）、`mainwindow.py`（主窗口）、`app.py`（启动流程）
- `tabexplorer/ai_actions.py` - AI 动作执行与 UI 请求桥接
- `tabexplorer/persistence.py` - 配置存储和会话收集/恢复
- `tabexplorer/instance.py` - 进程锁和本地实例消息
- `tabexplorer/runtime_validation.py`、`tools/validate_runtime.py` - 隔离的原生启动与性能趋势验证
- `tools/build_release.py`、[requirements/requirements-build.txt](../requirements/requirements-build.txt) - 可验证、失败保留旧版本的构建流程
- `tests/` - 回归测试；`tests/app_modules.py` 汇总各模块供测试读取，`patch_all()` 在所有导入了同一名称的模块中同时替换
- [requirements/requirements.txt](../requirements/requirements.txt) - Python 运行依赖列表；构建依赖列表通过相对路径引用它
- `tools/project_python.ps1` - 下载、校验并管理固定版本的项目本地 Python，统一安装、运行与构建入口
- `0_install_requirements.bat` - 安装项目本地 Python 及运行依赖（无需系统 Python）
- `1_run_TabEx.bat` - 源码运行脚本
- `2_build_exe.bat` - PyInstaller 打包脚本（仅使用项目本地 Python）
- [icons/generate_icon.py](../icons/generate_icon.py) - 应用图标生成脚本（需要 Pillow：`pip install pillow`）；在项目根目录运行 `python icons/generate_icon.py`
- [icons/TabExplorer.ico](../icons/TabExplorer.ico) - 应用图标，生成脚本输出到此位置，打包时直接使用

> `config/` 中的四个 JSON 配置文件、根目录的 `chat_history.json` 及损坏时保留的 `*.broken-*` 备份均为运行时自动生成的本地数据文件，已在 `.gitignore` 中忽略，不随仓库分发。
